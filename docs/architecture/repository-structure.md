# Repository structure

## Top level

| Path | Holds | Changed by |
| --- | --- | --- |
| `apps/api` | The API: one deployable, a modular monolith | Developer |
| `apps/web` | One Next.js application serving salon owner/admin/staff workspaces and the operator console; no customer web interface | Developer |
| `apps/web/scripts/` | The local custom server (`serve.mjs`); local startup is described in `docs/operations/environments-and-releases.md` | Developer |
| `apps/mobile` | The customer app: one Expo codebase for the shared container app and a dedicated app per salon. Created in milestone `M2-mobile` | Developer |
| `packages/api-contracts` | The TypeScript client generated from the API's OpenAPI document, exported per API module (`@salon/api-contracts/<module>`), used by the web app and the customer app | Developer (generated) |
| `packages/format` | Formatting of money, dates and phone numbers, shared by the web app and the customer app (CR-021, created by F23-S06). Further shared packages (`tokens`, `i18n`, `schemas`) are added with `M2-mobile` | Developer |
| `infra/` | Docker Compose for the local environment, its scripts, and `infra/postgres/` (the application role's definition) | Developer |
| `.github/` | Continuous integration | Developer |
| `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `.nvmrc`, `.sdkmanrc`, `.editorconfig`, `.env.example` | The workspace, the pinned tool versions and the settings of the local environment | Developer |
| `.local/` | Process ids and logs of the local environment. Never committed | The local scripts |
| `features/` | The plan and state of every feature and stage: specs, status, test cases, bugs, reviews | Lead, with the developer and QA writing their own files |
| `qa/` | QA automation, shared fixtures, release manifests | QA |
| `qa/scripts/` | The lifecycle tooling (`sdlc`) and the path-ownership check (`guard.py`) | Lead |
| `docs/` | Everything specific to this product. `docs/README.md` is the index | Lead (`docs/api/` is generated by the API build) |
| `.claude/skills/`, `.agents/skills/` | The process skills, and their Codex mirror | Lead |
| `.claude/agents/`, `.codex/agents/` | The developer and QA agent definitions for Claude Code and Codex | Lead |
| `AGENTS.md`, `CLAUDE.md` | Guidance read at the start of every session; each application folder has its own short pair | Lead |

The exact paths each role may write are enforced by `qa/scripts/guard.py`.

## What a release certifies

A release certifies one revision of these paths. If any of them changes after a release has been
verified, it is verified again (`release-cut` checks this):

```
apps packages infra package.json pnpm-workspace.yaml pnpm-lock.yaml docs/api qa/web qa/api qa/mobile qa/load qa/checks qa/shared
```

## What feature QA certifies

Feature QA records `integration.qa_revision`, a full commit SHA. Its certified product, automation
and pipeline paths are:

```
apps packages infra .github package.json pnpm-workspace.yaml pnpm-lock.yaml .nvmrc .sdkmanrc docs/api qa/web qa/api qa/mobile qa/load qa/checks qa/shared qa/scripts qa/package.json qa/pnpm-lock.yaml qa/playwright.config.ts qa/tsconfig.json
```

`qa/scripts/sdlc pr-check` and the live merge gate refuse changes in these paths after that
revision, and also check the feature's `cases.md` and each stage's `spec.md` and `cases.md`.
Feature/QA metadata and documentation commits may follow. The tooling's
`schema.FEATURE_QA_PATHS` is the machine-readable counterpart of this list.
